# Security, caching, and static hosting

This is a static browser app without an application backend. `public/_headers` is the shared policy template. After exporting HTML, `scripts/build-security.mjs` adds hashes for the exact inline scripts in that build. Cloudflare Workers Static Assets reads the generated `_headers` directly. `npm run build:workers` generates the production static assets and policy.

Sites' default static serving does not apply `_headers` and serves recognized files before invoking a Worker. The dedicated preview package generated by `scripts/build-sites.mjs` therefore bundles the exported files into a standalone static response Worker. It applies the shared headers, MIME types, ETags, conditional/HEAD responses, and real 404s. Files decode lazily and the build enforces a 3 MB compressed script budget. It has no game logic, database, API, or user state. Cloudflare Workers Static Assets uses ordinary static files with native rules and does not need this embedding adapter.

## Response headers

- Content Security Policy permits scripts from the app origin and build-specific SHA-256 hashes. It does not allow `unsafe-inline` JavaScript, `unsafe-eval`, or reused nonces. All generated inline scripts, including JSON-LD and hydration data, are checked against the policy.
- Styles allow inline CSS for React, UI primitives, and local font declarations. Fonts, images, and network requests otherwise default to the same origin. No third-party analytics or font origins are allowlisted.
- Framing, embedded objects, media, and base-URL injection are disabled. Workers, manifests, and forms stay on the app origin. `X-Frame-Options: DENY` supplements CSP framing protection.
- HSTS lasts one year on HTTPS responses. It intentionally does not opt other subdomains into HSTS or request preload registration.
- MIME sniffing and cross-origin resource embedding are disabled. Referrers use `strict-origin-when-cross-origin`.
- Permissions Policy disables unused camera, microphone, location, payment, sensor, and USB capabilities while preserving same-origin clipboard writes and Web Share.

The CSP is emitted as two policies to stay below Cloudflare's 2,000-character header-line limit. Browsers enforce both policies together. The build fails if that limit or the 100-rule limit is exceeded. The static 404 page has no hydration scripts, and internal Vite/client-entry manifests are removed from public output.

If adding external scripts, analytics, embedded content, or a platform preview toolbar, review their CSP requirements explicitly. Inline scripts injected after the build will be blocked. Do not solve that by adding a blanket `unsafe-inline` script exception. Provider-generated authentication/error pages can have their own headers.

## Cache policy

| Resource                                                      | HTTP cache policy                        |
| ------------------------------------------------------------- | ---------------------------------------- |
| Homepage, HTML shell, RSC text, manifest, service worker      | Revalidate on every request (`no-cache`) |
| Hashed JavaScript, CSS, and font assets under `_next/static/` | One year, immutable                      |
| Unversioned icons and font license documents                  | One day, then revalidate                 |
| robots.txt, sitemap.xml, llms.txt, Markdown guide             | One hour                                 |
| Missing pages / 404                                           | `no-store`, `noindex`                    |

Cloudflare Workers Static Assets supplies CDN compression and conditional response handling. The app does not override these with a separate surrogate cache that could outlive the browser policy.

Offline caching is separate from HTTP caching. The service worker precaches a consistent release and activates after older tabs close. Its version includes response-header rules, so a policy-only change replaces previously cached HTML too. Registration uses `updateViaCache: 'none'` to bypass HTTP caches when checking worker updates. A tab already open offline continues using its installed release until it reconnects and updates.

## Deploy on Cloudflare Workers

`npm run build:workers` exports `dist/client`, and `cloudflare/wrangler.jsonc` selects that directory for `preview:workers` and `deploy:workers`. Workers applies the generated `_headers` directly. Explicit `404-page` handling preserves HTTP 404 responses for unknown paths. `/404.html` and `/404` have error-document headers for HTML URL normalization. Existing files use native asset serving. The hosting-only `cloudflare/worker.mjs` fallback fetches the static error document and preserves its security headers, then sets `no-store` and `noindex` on HTTP 404 responses. Missing navigations use this handler too. This prevents missing files from inheriting the hashed-asset cache policy; it adds no game backend. Use the [Workers deployment settings](cloudflare-workers.md) for dashboard commands, CLI, Node version, and custom domain setup.

After a real Workers deployment, inspect response headers on the homepage, one hashed asset, manifest, service worker, and a missing URL. Confirm the same checks on the public hostname, since a reverse proxy or authentication gateway can change responses. Repository checks validate generated policy and artifacts, not account-level firewall settings.

The production hostname is **https://mathmagician.lowkey.tools/**. Its custom-domain route is declared in `cloudflare/wrangler.jsonc` and applied by `wrangler deploy`. The canonical root slash stays consistent; the route pattern itself is a hostname without a scheme, slash, or wildcard.

## Sites preview and local serving

For Sites, use `npm run build` and pass the generated `work/sites-deploy/` project directory to the Sites packaging helper. It contains the standalone response Worker and copied Sites metadata. Do not include a separate `dist/client/` directory in that preview archive: Sites would serve those files before the response policy. The original `dist/client/` remains the native asset directory for Cloudflare Workers. For local HTTP checks, `npm start` applies the generated `_headers` policy.
